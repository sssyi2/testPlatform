## 二、自动录屏（推荐，可重复）

不需要人工点鼠标：录屏脚本会用 Playwright **真的去操作平台界面**，同时录制浏览器画面，
最后用带 x264 的 ffmpeg 转成 mp4，并自动生成录像说明与报告附件。

```powershell
cd E:\testPlatform\code
node tools\record-demo.mjs                      # 默认输出 2026xxxx-小商城示例-全流程测试.mp4
node tools\record-demo.mjs --name 我的演示 --headed   # 自定义文件名 / 显示浏览器窗口
```

脚本会：拉起独立实例（端口 4521、数据目录 `code/.recording-data`，**不影响你正在用的 4519 实例**）
→ 导入示例 → 打开用例看配置 → 运行全部 → 实时日志与断言 → HTML 报告 → 被测软件现场 →
执行记录，全程底部有步骤字幕、点击前高亮目标元素。

前置：Chromium（`node tools/install-browsers.mjs`）+ 带 x264 的 ffmpeg（脚本缺失时会提示安装命令）。

## 三、人工录屏（可选，想要"真人操作"观感时用）

1. 启动演示环境并打开界面：
   ```powershell
   powershell -ExecutionPolicy Bypass -File tools\start.ps1
   ```
2. 录制工具（Windows 自带，二选一）：

   | 工具 | 开始/停止 | 产物位置 |
   | --- | --- | --- |
   | Xbox Game Bar | `Win + Alt + R` | `%USERPROFILE%\Videos\Captures`（视频/捕获） |
   | 截图工具（Win11） | `Win + Shift + S` → 选「录制」 | 录完在截图工具里「另存为」mp4 |

3. 分镜脚本（约 5 分钟）：

   | # | 画面 | 讲解要点 |
   | --- | --- | --- |
   | 1 | 终端执行 `node tools\demo.mjs --serve` | 「一条命令同时拉起被测软件和测试平台」 |
   | 2 | 浏览器打开平台界面 | 布局：左侧项目、中间用例、右侧执行面板 |
   | 3 | 点「导入示例」 | 「11 个用例，8 API + 3 Web，声明式配置，不写代码」 |
   | 4 | 打开一条 API 用例的编辑器 | 请求、`{{baseUrl}}`、抽取 `token`、断言（状态码/JSON/耗时） |
   | 5 | 点「运行全部启用」 | 实时日志、断言 PASS/FAIL、失败自动截图 |
   | 6 | 打开 HTML 报告 | 汇总数字、失败断言「期望 vs 实际」、截图证据 |
   | 7 | 切到被测软件页面 | 「这就是被测的小商城，4 个缺陷都能在这里复现」 |
   | 8 | 终端执行 `node tools\selftest.mjs` | 「CI 友好的自测：退出码 0 说明平台自身完好」 |
   | 9 | 结尾 | 「同样流程可以对任意 HTTP 接口或网页系统执行」 |

4. 录完放到本目录，命名 `YYYYMMDD-<被测对象>-<场景>.mp4`，补一个同名 `.md`（模板见 `example-record.md`），
   并在上面的表格里登记。

## 四、核对要求

登记表里的数字必须与录像里真实出现的一致；平台每次执行的真实结果可在 `code/data/runs/` 下复核，
也可以打开 `/api/runs/<执行ID>/report` 重看报告。录像里的失败用例必须是**被测软件的真实缺陷**，
不能是平台自身的故障——否则录像失去意义。
