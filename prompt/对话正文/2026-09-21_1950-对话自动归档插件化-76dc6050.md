## 做了什么

**新插件 `dsh-archive-watch`**（零依赖，只用 Node 内置模块），装在 `C:\Users\sfy\.dsh\plugins\dsh-archive-watch`，并作为 bundle 进了 web profile 的 `dsh.profile.bundles`：

- **主触发器**：监听宿主的 `session/event`（提交后的追加事件流）。一轮说完话、事件静默 3 秒即归档 —— 这正好补上「最后一条回复落在最后一次工具调用之后」的空档。
- **兜底轮询**：每 60 秒检查会话日志指纹（文件数 + 最新 mtime），事件监听失效也不漏。
- 只对 `workspaces` 里配置的工作区（当前 `E:/testPlatform`）生效；无关会话的事件被忽略。
- 所有副作用（定时器、事件监听、子进程、日志）都挂在 `ctx.effect` 上，卸载即全部回收。
- 插件**不重写归档逻辑**，只是按需跑 `code/tools/dsh-archive.mjs --workspace <ws>`；日志仍写 `prompt/.archive-watch.log`，格式与原来一致，所以 AGENTS.md 里那条检查命令继续有效。
- 为什么放宿主平面而不是 preset：守护必须全进程一份、跨会话共享，放进 preset 会变成每个会话各起一份互相争抢写入。

**顺手修掉一个既有 bug**：`.dsh/` 里那套 hook 从来没挂载过。profile 的 `cordis.patch.yml` 写的是 `- name: '@deepseek-ai/dsh-hooks-claude-code'`，既没有 `id` 也不是 `insert`，loader 直接拒收（`patch: id is required for non-insert patches`），每次启动只多打一行警告。现在全局那条死配置已清掉（改为注释指向插件），`.dsh/profile-patch.yml` 改成正确的 `- insert:` 形式 —— hook 现在是真正可用的可选双保险。

### 一点没验证到的

`.dsh/profile-patch.yml` 那条可选的 hook 双保险我没实际启动验证（只确认了 `dsh --patch` 选项还在、`@deepseek-ai/dsh-hooks-claude-code` 包还在）。它是可选路径，主力是插件，不影响归档。

另外注意：`dsh` 命令仍是 npm 全局的 `0.1.5-rc.1`，而你在用的 GUI 是打包版（`app.asar`）。两者读同一份 `~/.dsh` 配置，所以 `dsh plugin add` 照常有效；但如果以后发现命令行版和桌面版行为不一致，原因在这里。
